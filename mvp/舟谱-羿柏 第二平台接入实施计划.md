# 舟谱-羿柏 第二平台接入实施计划

## Context（为什么做）

EC101 促销费用数据底座的 MVP 库 `mvp/ec101_mvp.db` 目前只接入了第一个平台 **快马-兴路强**（满减/满赠/优惠券已跑通，24 表中 21 张有数据，STANDARD 层 `std_field_mapping`/`std_quality_check` 仍为 0 行）。现在接入 **第二个平台 舟谱-羿柏**，验证底座的多平台承载能力，并首次把 STANDARD 层填起来。

本轮三个已确认决策：
1. **共库追加**：舟谱作为新的 `dealer_platform=羿柏/舟谱` 写进同一个 `ec101_mvp.db`；兴路强数据按 `dealer_platform_id` 隔离，完全不动。
2. **配置驱动 + 薄适配**：把 skill 已算好的舟谱字段映射灌进 `std_field_mapping` 表作为映射真源，通用加载器读表落库；舟谱特有解析怪癖放薄适配层。
3. **范围＝主数据 + 订单落地**：只落 客户/商品主数据 + 订单明细 + RAW 血缘进 CORE 表。**返券核算、满赠核算、销售明细/XD、活动明细、退货冲回、RESULT 层 本轮都不做。**

已字节级核验的数据事实：
- 权威源目录 = `第三阶段数据库设计\舟谱-羿柏-试点`（用户指定）。phase-2 的 `第二阶段验证\舟谱-羿柏` 不含满减销售明细，不是本轮源。
- 舟谱表头在 **第 4 行**（活动明细在第 3 行），第 1–3 行是 标题/导出时间/筛选条件；兴路强表头在第 1 行。
- `readers.py` 两处限制：① `read_table` 无 `header_row` 参数（永远把第 1 行当表头）；② `_read_ooxml` 第 131 行 rels 正则假设 `Id=` 在 `Target=` 之前，而舟谱销售明细是 **Target-first** → `KeyError:'xl/'`。（第 135 行已 `lstrip('/')`，前导斜杠不是问题；唯一根因是 131 行正则顺序依赖。）本轮虽不加载销售明细，但仍修复①②：① 是读舟谱任何文件的硬前提，② 是用户答案 B 明确指出的缺陷。
- 舟谱"满减"实为 **288 返 15 返券**（答案 C），本轮不核算；**暂不算退货冲回**（答案 C），故 `return_qty` 留空。
- 舟谱 skill 映射 = `outputs\缇挎煆\run.json`（442949 字节，`缇挎煆` 是 `羿柏` 的 mojibake）；seed 脚本按 `platform=='舟谱'` 字段选取，不靠目录名。
- 根目录 `客户档案-20260914.xlsx`/`商品档案-20260914.xlsx` 与 `满赠\客户档案.xlsx`/`满赠\商品档案.xlsx` 字节相同（重复副本）——主数据只加载一次。

## 实施步骤

### 步骤 0 — 修 readers.py（前置，独立可验）
- `read_table` 增 `header_row=1`：`header = rows[header_row-1]`，`data = rows[header_row:]`；越界返回空。默认 1 → 兴路强零回归。
- 第 131 行改为逐个 `<Relationship>` 解析、Id/Target 分别取（顺序无关）：
  ```python
  rid2target = {}
  for m in re.finditer(r'<Relationship\b[^>]*>', rels):
      tag = m.group(0)
      rid = re.search(r'\bId="([^"]+)"', tag)
      tgt = re.search(r'\bTarget="([^"]+)"', tag)
      if rid and tgt:
          rid2target[rid.group(1)] = tgt.group(1)
  ```
- 验证：读 phase-3 `满减\舟谱-羿柏-销售明细-20260826-20260908.xlsx`（Target-first + 无 sharedStrings）应成功返回数据行；再读兴路强任一文件确认无回归。

### 步骤 1 — 灌 std_field_mapping（配置驱动真源）
- `seed_std_mapping_zhoupu.py`：glob `outputs/*/run.json`，选 `platform=='舟谱'` 的那份；遍历 `field_mappings`，**只保留 `经销商原始字段` 为真实列名的行**（排除 `—` 与 `Skill计算`，避免 `UNIQUE(platform,module,raw_field)` 撞键）；写入：`platform='舟谱'`, `module=模块`, `raw_field=经销商原始字段`, `ec101_field=EC101标准字段`（`—`→NULL）, `confidence=证据等级`, `is_non_v1=(字段关系=='非V1字段')`, `gap_flag=状态`。
- 幂等：先 `DELETE FROM std_field_mapping WHERE platform='舟谱'`。
- **补齐**（用户答案 A 预期"可能需补齐"）：灌完跑 dry-run，打印 phase-3 实际表头里**未在 std_field_mapping 出现的列**，人工补别名。已知需补：`单位名称（大）`→订货单位、`订单数量（大）`→订货数量（run.json 基于 phase-2，phase-3 的（大）后缀列可能缺）。

### 步骤 2 — 通用映射工具 std_mapping.py
- `load_mapping(conn, platform, module) -> {raw_field: ec101_field}`（取 `is_non_v1=0` 且 `ec101_field` 非空）。
- `map_rows(header, rows, mapping) -> [{ec101_field: value}]`。
- `EC101_TO_CORE`（ec101 标准字段 → CORE 列，平台无关，按目标表分组）：
  - **customer**：客户编号→platform_customer_no, 客户名称→customer_name, 客户类型→customer_type, 客户等级→customer_level, 客户标签→customer_tag, 客户区域→customer_region, 所属业务员→salesperson_name, 建档时间→created_at, 客户状态→status
  - **product**：平台商品编号→platform_product_no, 商品名称→product_name, 商品品牌→brand, 商品目录/品类→category, 商品规格→spec, 商品条码→barcode, 基本单位→base_unit, 箱规→box_conversion, 太古产品代码→swire_product_code
  - **order_header**：订单编号→order_no, 下单时间→order_time, 订单状态→order_status, 支付方式→pay_method, 支付状态→pay_status, 订单来源→order_source, 订单类型→order_type
  - **order_line**：订货数量→order_qty, 订货单位→order_unit, 基本单位数量→base_qty, 基本单位→base_unit, 优惠前金额→pre_discount_amount, 单价→unit_price, 退货数量→return_qty（`discount_amount` 为计算列，见步骤 3）

### 步骤 3 — 舟谱薄适配 + 加载 ingest_zhoupu.py
- 连接 `ec101_mvp.db`（append，**不删库**），`PRAGMA foreign_keys=ON`。
- 幂等清理（只删羿柏，按 FK 顺序）：`order_line → order_header → product → customer`（`WHERE dealer_platform_id=羿柏`）；RAW 按 `batch_code` 删。
- `dealer_platform`：SELECT 复用 else INSERT（`dealer_name='羿柏'`, `platform_name='舟谱'`）。
- **客户主数据**：读 `客户档案-20260914.xlsx`(header_row=4) → map → customer。`platform_customer_no ← 客户唯一序号`（**客户编码列为空**，不可用）；只加载根目录这份，跳过 `满赠\客户档案.xlsx` 副本。
- **商品主数据**：读 `商品档案-20260914.xlsx`(header_row=4) → map → product。`platform_product_no ← 商品唯一序号`（**编号列为空**）；`box_conversion ← 单位换算`('1箱=15瓶')；跳过 `满赠\商品档案.xlsx` 副本。
- **订单**：读 8 个订单明细（5 满减 0826-0908 + 3 满赠 0819-0826，header_row=4）→ map → order_header + order_line。
  - `order_header`：`order_no ← 订单编号`(SXD…)；`customer_id` 由 **客户名称** 匹配（客户编码空）；`pay_method ← 支付时间列`（**舟谱陷阱：该列值是 '货到付款'，是方式不是时间**，RAW_TO_STANDARD 已 支付时间→支付方式）；order_source/order_type 舟谱无 → NULL。`UNIQUE(dealer_platform_id, order_no)`：满赠 0819-0821 与 0821-0823 窗口重叠，用 `INSERT OR IGNORE` 去重并记录重复数。
  - `order_line`：`product_id` 由 **商品条码** 匹配（商品编号空）；赠品/无条码行 → product_id NULL（SQLite 中 `UNIQUE(order_id,NULL)` 不冲突）。`order_qty ← 实际数量/订单数量（大）`（两者都映射到 订货数量，map 已统一）；文本 "1箱" 用 `to_num` 取数。`base_qty`：舟谱订单明细**无基本单位数量列** → 按 `order_qty × 每箱换算`（product.大单位换算）计算（仅当 order_unit=箱/大单位），匹配不到商品则留空。`discount_amount = 优惠前金额 − 实际金额`（舟谱无独立优惠金额列；使 pre_discount − discount = 实付）。`unit_price ← 实际单价`。`return_qty ← NULL`（答案 C）。
- **RAW 血缘**：新建 `raw_import_batch`(`batch_code='ZHOUPU-YIBAI-MASTER-ORDER-20260923'`, `source_platform='舟谱'`, `dealer_name='羿柏'`, `operator='小凡'`)；每个加载文件一行 `raw_file`(`module`=客户/商品/订单, `file_signature='OOXML'`, `read_method='readers.read_table(header_row=4)'`, `header_row=4`, `data_rows`=实际行数)。
- 末尾打印验证查询。

## 验证（端到端，只读 SQL）

1. **readers 修复**：单独读 phase-3 销售明细成功（不加载，仅证明修复）；兴路强任一文件无回归。
2. **STANDARD 非空**：`SELECT COUNT(*) FROM std_field_mapping WHERE platform='舟谱'` > 0；抽查 客户唯一序号→客户编号、片区→客户区域、支付时间→支付方式。
3. **隔离性（关键）**：加载前后，兴路强 dealer_platform 的 customer/product/order_header/order_line 计数**逐一不变**。
4. **主数据**：羿柏 customer ≈ 2492、product ≈ 2655（以实际为准）；`platform_customer_no`/`platform_product_no` 全非空且唯一。
5. **订单**：order_header 数 = 8 文件 distinct order_no（去重后）；`PRAGMA foreign_key_check` 无输出；抽查 `SXD260827000153` 的 header + lines + 金额对得上源文件。
6. **血缘**：`raw_import_batch` 1 行 + `raw_file` 10 行（2 主数据 + 8 订单），`header_row` 均 = 4。
7. **未映射列报告**：dry-run 输出的"phase-3 有但 std_field_mapping 无"的列清单应为空（补齐后）。
8. 打印 客户重名数、同单同商品多行数（UNIQUE 冲突风险），供人工判断。

## 本轮不做 / 风险

- **不做**：返券(288 返 15)核算、满赠核算、销售明细/XD 加载、活动明细、退货冲回、cross_mapping、任何舟谱 RESULT 行。
- **风险**：① 客户按名称匹配（客户编码空）——重名会错配，需打印重名清单；② 商品按条码匹配——赠品/无条码项 product_id 落空；③ base_qty 依赖商品主数据换算，未匹配则空；④ run.json 基于 phase-2，phase-3 列名可能有出入——靠"补齐 + 未映射报告"兜底；⑤ `UNIQUE(order_id, product_id)` 对同单同商品多行会冲突——加载前核验，合并或忽略。
