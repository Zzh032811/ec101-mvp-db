# EC101 费用运营台局域网共享部署方案

## 1. 方案定位

本方案将一台 Windows 电脑作为局域网临时服务器，供同一办公网络内的业务员访问 EC101 费用运营台。Mac 和其他 Windows 电脑作为访问端。

适用范围：SQLite、只读 API、业务数据查询、筛选、详情和 CSV 导出。不开放修改、审批、结算和支付回写。

## 2. 网络结构

```text
业务员电脑 ─┐
业务员电脑 ─┼── 办公局域网 ── Windows 临时服务器
业务员电脑 ─┘                         ├─ 前端：3000
                                      ├─ API：8787
                                      └─ SQLite：mvp/ec101_mvp.db
```

业务员访问 `http://Windows服务器IP:3000`，前端访问 `http://Windows服务器IP:8787`。

## 3. Windows 环境要求

- Windows 10 或 Windows 11；
- Python 3.9+；
- Node.js 22+；
- Git；
- 与业务员电脑连接同一办公网络；
- 建议配置固定局域网 IP。

## 4. 获取项目

在 PowerShell 中执行：

```powershell
cd D:\Projects
git clone <GitHub项目地址>
cd ec101-mvp-db
```

如果项目已经存在，执行 `cd D:\Projects\ec101-mvp-db` 后再执行 `git pull`。

确认以下文件存在：

```text
D:\Projects\ec101-mvp-db\mvp\ec101_mvp.db
D:\Projects\ec101-mvp-db\api\server.py
D:\Projects\ec101-mvp-db\ec101-fee-platform-v1\package.json
```

## 5. 获取服务器 IP

执行 `ipconfig`，找到当前网络适配器的 IPv4 地址，例如 `192.168.1.50`。下文以此 IP 为示例，实际执行时替换为真实 IP。

## 6. 启动只读 API

打开第一个 PowerShell 窗口：

```powershell
cd D:\Projects\ec101-mvp-db
py api\server.py --host 0.0.0.0 --port 8787
```

保持窗口运行。服务器本机访问 `http://127.0.0.1:8787/health`，返回 `status: ok` 且数据库路径指向 `mvp\ec101_mvp.db`，表示 API 正常。

## 7. 启动前端

打开第二个 PowerShell 窗口：

```powershell
cd D:\Projects\ec101-mvp-db\ec101-fee-platform-v1
npm install
$env:NEXT_PUBLIC_EC101_API_URL = "http://192.168.1.50:8787"
npm run dev -- --host 0.0.0.0
```

业务员通过浏览器访问 `http://192.168.1.50:3000`。不要访问 `localhost:3000`，因为那代表业务员自己的电脑。

## 8. Windows 防火墙

允许“专用网络”访问以下 TCP 端口：

| 用途 | 端口 |
|---|---:|
| EC101 前端 | 3000 |
| EC101 只读 API | 8787 |

不要开放到公用网络，不要进行公网端口映射，也不要关闭 Windows 防火墙。

## 9. 业务员验证

打开 `http://192.168.1.50:3000`，进入“数据底座 → 业务数据”，检查订单加载、经销商筛选、关键词搜索、详情和 CSV 导出。

## 10. 常见问题

### 页面打不开

检查前端窗口、Windows 服务器 IP、网络是否相同，以及 TCP 3000 防火墙规则。

### 页面提示数据服务不可用

在业务员电脑访问 `http://192.168.1.50:8787/health`。若打不开，检查 API 是否运行、是否使用 `--host 0.0.0.0`，以及 TCP 8787 防火墙规则。

检查前端 API 地址：

```powershell
echo $env:NEXT_PUBLIC_EC101_API_URL
```

应显示 `http://192.168.1.50:8787`。

### IP 发生变化

重新执行 `ipconfig`，修改前端 API 地址并重启前端。建议为服务器配置固定 IP。

## 11. 数据更新

更新 SQLite 前应停止 API、备份 `mvp\ec101_mvp.db`、替换数据库文件、重新启动 API，并检查业务数据和核算结果。不要让多人同时编辑 SQLite 文件，也不要通过浏览器直接提供数据库文件下载。

## 12. 安全边界

该方案适合内网试用，不适合正式生产：当前没有登录、业务员权限隔离、正式审计、线上 HTTPS 和高并发能力。禁止将端口暴露到公网，禁止在公用 Wi-Fi 上开放，禁止把数据库文件发给业务员。

## 13. 后续线上化

稳定试用后迁移为“业务员浏览器 → 线上费用运营台 → 线上 API → MySQL/PostgreSQL 统一数据库”，再增加登录、角色权限、导出审计、数据备份、故障恢复和 HTTPS。前端接口契约保持不变，Mac 和 Windows 只访问统一线上地址。

## 14. 结论

Windows 局域网共享可以作为 EC101 费用运营台的第一阶段试用方案：部署简单、数据真实、Mac 和 Windows 均可使用。但它仍是“单台 Windows + SQLite + 内网访问”的临时方案，业务试用完成后应迁移到线上 API 和统一数据库。
