# 输入数据质检规则

## 目的

在字段映射和活动重算之前，确认上传的活动数据包与活动任务卡一致。质检不判断活动是否执行正确，只判断数据是否可进入验证。

## 必查项目

| 检查项 | 通过标准 | 不通过时的处理 |
|---|---|---|
| 文件可用性 | 必需文件存在、可读取且有真实数据行 | 缺失或空文件为 P0 阻断 |
| 日期覆盖 | 订单、销售、活动执行明细覆盖任务卡要求的活动/观察期 | 缺口为 P0 阻断，不以零参与代替 |
| 活动配置对应 | 活动 ID 一致；无 ID 时名称、类型、起止时间均一致 | 错图或错配置为 P0 阻断 |
| 经销商/平台对应 | 来源文件与任务卡经销商、平台一致，或有可解释的共同供货主体 | 无法确认时为 P0 阻断 |
| 关联键 | 订单、销售、活动执行明细存在可用订单号或明确替代关联键 | 无法归因时为 P0 阻断 |
| 关键字段 | 订单状态、活动规则/实际权益等与本次验证有关的字段可用，或已明确 Gap | 按影响标注 P0/P1 Gap |
| 文件版本 | 文件名或任务卡记录可区分活动、资料类型、期间和版本 | 不明确时为 P1 Gap；发现错文件则 P0 阻断 |

## 质检结果

- `通过`：所有 P0 检查通过，可以进入验证。
- `条件通过`：无 P0 阻断，但存在 P1/P2 Gap；继续验证并保留风险。
- `阻断`：至少一项 P0 检查不通过。只输出收数缺口和受影响范围，活动或费用结论为 `未验证`。

## 日期覆盖原则

以任务卡定义的业务时间为准，不以文件名、导出日期或截图生成时间替代。导出时间字段必须与验证口径一致；例如按下单时间验证活动资格时，应检查订单下单时间的最小值和最大值。
